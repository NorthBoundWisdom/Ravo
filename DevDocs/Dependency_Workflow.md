# FreeCM source-root dependency integration workflow

This document defines how Ravo uses FreeCM to manage third-party source, switch
to a local editable dependency checkout, and turn an integration result into a
reproducible pinned baseline. These rules apply on Windows, macOS, and Linux.
Example local paths describe active machine state only and must not enter a
tracked template.

## Sources of truth and directory ownership

Inspect the machine-local active lock first to determine what a checkout really
uses; do not infer it from the committed template alone.

| Path | Ownership and purpose |
| --- | --- |
| source_roots.lock.jsonc.in | Version-controlled direct-dependency baseline for review and release. Permanent pins, shared CMake defaults, and dependency-list changes belong here. |
| source_roots.lock.jsonc | Ignored active lock. It determines current mode, manual paths, and local CMake configuration. It may be edited for integration but must not be committed. |
| build/dependency_seed_repos/* | Local Git seeds prepared by --init. They provide objects and refs for offline resolution/materialization and are not parent-repository source. |
| build/dependency_source_roots/* | Concrete source roots created by --update/materialize. They are replaceable and must never be modified directly. |
| CMakePresets.json | Current-host preset generated by --update. Do not edit or commit it. |
| .freecm.workspace.lock | Short-lived mutual-exclusion directory shared by Python workflow and the FreeCM extension. Do not create or commit it manually. |

The root lock declares Ravo direct dependencies only. If a dependency lock
template declares a sibling, FreeCM resolves the transitive closure recursively
from local seeds. Do not repeat every transitive dependency in the root lock.

Current direct dependencies are LibRaw and GeoControls. Quill resolves through
find_package(quill CONFIG REQUIRED) from the host CMAKE_PREFIX_PATH, such as
vcpkg, Homebrew, or Qt prefixes, and does not enter the source-root lock. Use
these logical dependency names as depsManualPath keys, not guessed directories.

## FreeCM submodule tracking

This repository tracks FreeCM/master through .gitmodules. Only for an explicitly
requested FreeCM refresh, start from a clean parent-repository root:

~~~text
git status --short --branch
git -C FreeCM status --short --branch
git submodule update --remote --checkout FreeCM
~~~

Do not run git pull inside the normally detached FreeCM checkout. An unchanged
gitlink is a no-op. If it changes, explain the git submodule status prefix and
run:

~~~text
python3 -m repomgrcpp.tools.repo_tool check-lock-compat --repo-root .
python3 FreeCM/tools/validate_repo_commands.py .
python3 configs/source_roots.py show --format json
python3 configs/source_roots.py resolve --format json
python3 configs/source_roots.py verify
~~~

Then configure/build Ravo on the current platform. Stop a refresh when the
parent or submodule has unrelated changes; do not commit or push a gitlink
without an explicit user request.

## Dependency modes

- pinned uses the exact dependencies.<name>.commit and is the required
  reproducible baseline for the tracked template.
- latest uses the newest ref/commit locally visible in a seed. It never fetches
  and is appropriate only for temporary resolution, not a release baseline.
- manual uses a real checkout only for a non-empty depsManualPath.<name>. An
  empty string keeps managed resolution, so a single dependency can be
  integrated without rewriting all paths.

manual and latest are active local state. Never write machine paths or moving
refs into source_roots.lock.jsonc.in.

## Local CMake and preset configuration

cmakeEnvironment, cmakeCacheVariables, and terminalPath are driven by the active
lock. FreeCM applies shared values first, then overlays the host win, mac, or
linux map. Personal SDK locations, temporary tool paths, and checkout-specific
switches remain in the active lock or external toolchain environment; only
reviewed cross-machine defaults enter the template.

Ravo packaging uses the same mechanism. The platform
cmakeCacheVariables.<platform>.RAVO_PACKAGE_RUNTIME_SEARCH_PATHS value is a
semicolon-separated list of deployable dynamic-library directories. The tracked
template gives only three-platform path shapes. Replace <user>, Qt kit, and
package-manager paths in the active lock, then run --update. Ravo CMake does
not infer them from CMAKE_PREFIX_PATH, Zlib/PNG imported targets, or host
defaults; missing values make Config fail directly.

An explicit active-lock cmakeCacheVariables.CMAKE_PREFIX_PATH completely replaces
FreeCM-managed dependency install prefixes; it is not appended automatically.
Source-root environment resolved by --update overrides same-named
cmakeEnvironment values so actual pinned/manual roots enter the preset. After
any change, rerun --update instead of patching generated CMakePresets.json.

## First preparation and maintenance

Prepare a workspace:

~~~text
git submodule update --init FreeCM
python configs/source_root_workflow.py --init
python configs/source_root_workflow.py --update
~~~

On macOS/Linux, python may be written as python3. --init is the only dependency
step allowed to use the network. It creates an active lock from the template
when needed, clones or prepares the seed closure, and prepares declared remote
assets.

--update is fully offline. It acquires .freecm.workspace.lock, reads the active
lock and existing seed closure, resolves pinned/latest/manual concrete roots,
materializes or refreshes build/dependency_source_roots/* (or selects manual
checkouts), writes source-root environment into root CMakePresets.json, and
runs the host update callback. It never clones, fetches, pulls, downloads
assets, compiles dependencies, configures Ravo, or runs tests. If a seed is
missing, explicitly run --init; do not hide a network step in Build/Test/Run.

| Action | Network | Effect and boundary |
| --- | --- | --- |
| --refreshpin | Prohibited | Requires active lock and template to be pinned; aligns active dependency commits with the committed template only. It neither switches mode nor materializes roots. |
| --pinlatest | Prohibited | Selects a local candidate from the newest commits visible in seeds and performs an offline update. It neither fetches nor proves publication. |
| --update | Prohibited | Materializes roots from the current active lock, generates host preset, and runs the update callback. |
| --cleanbuild --dry-run | Prohibited | Lists conservative cleanup targets and deletes nothing. |
| --cleanbuild | Prohibited | Cleans normal build output while preserving dependency_seed_repos and dependency_source_roots. |

latest is only for explicit dependency refresh and is not committable state. The
CLI --pinlatest leaves the active lock in latest; the FreeCM panel action with
the same name writes a pinned snapshot, so finalization differs. Full CLI
refresh order: confirm every related worktree is clean and privately snapshot
the lock → networked --init → offline --pinlatest → quick Ravo validation →
verify remote SHA → update committed template → explicitly return active-lock
depsMode to pinned → --refreshpin → --update → verify/configure/build/test.
When a candidate fails, leave the template unchanged; restore the original lock
and materialized state with --update, then report both failure and restoration.

Always run --cleanbuild --dry-run and inspect targets before cleanup. Do not
replace FreeCM containment checks with custom recursive deletion.

## FreeCM project-command manifest

configs/freecm.commands.jsonc uses schema version 2. Config is active context.
Every Build, Run, Test, and Package variant declares non-empty configurations
and binds a compatible Config. Downstream actions must not execute Configure
implicitly; Config inputs/outputs decide whether generated state is ready or
stale.

After changing the manifest, configuration entry point, or readiness contract:

~~~text
python3 FreeCM/tools/validate_repo_commands.py .
~~~

Ravo uses separate Configs for Debug/Release and Windows/macOS/Linux.
Build/Run/Test/Install use Ravo/tools/freecm_project.ps1 or
Ravo/tools/freecm_project.py rather than duplicate long CMake arguments.

## Inspect active state

Before changing a dependency or diagnosing ownership, run:

~~~text
python configs/source_roots.py show --format json
python configs/source_roots.py resolve --format json
python configs/source_roots.py verify
~~~

- show reports final environment variables and concrete roots.
- resolve reports direct/transitive closure, every dependency's mode, commit,
  manual override, parent/child relation, and path.
- verify confirms final roots exist and contain files required by
  configs/source_roots.py.

For deeper offline diagnosis:

~~~text
python configs/source_roots.py graph --format json
python configs/source_roots.py graph --format dot
python configs/source_roots.py audit --format json
python configs/source_roots.py policy-check --format json
python configs/source_roots.py explain-conflict <dependency-name> --format json
~~~

This repository's generic FreeCM binding provides show rather than a status
subcommand that another host might expose. Treat the real output of
python configs/source_roots.py --help as authoritative.

## Local dependency integration

### 1. Select a real editable checkout

Prefer a developer-supplied sibling checkout, such as D:/work/LibRaw on Windows
or /work/LibRaw on macOS/Linux. Do not edit
build/dependency_source_roots/LibRaw as source: a later --update may replace it.

If no separate checkout exists and a FreeCM seed is explicitly selected as a
temporary real dependency repository, use
build/dependency_seed_repos/<repoName> only after checking:

~~~text
git -C build/dependency_seed_repos/<repoName> status --short --branch
~~~

The seed must have a known branch/commit and no unknown changes. Complete manual
wiring before editing it. Once locally modified, do not treat it as a freely
refreshable/deletable cache. A manual path to a managed seed is still managed by
--init: a clean seed can sync to its remote default branch and a dirty seed
rejects overwrite. Do not run --init during seed integration; prepare other
missing seeds beforehand.

### 2. Change only the machine-local active lock

Set depsMode to manual in source_roots.lock.jsonc and fill only the dependency
being integrated. Preserve the actual file's schemaVersion, dependencies,
assets, and local CMake configuration:

~~~jsonc
{
  "depsMode": "manual",
  "depsManualPath": {
    "LibRaw": "D:/work/LibRaw",
    "GeoControls": ""
  }
}
~~~

Use / in Windows JSON paths to avoid backslash escaping. Empty entries keep
pinned/managed resolution. Do not modify or commit
source_roots.lock.jsonc.in for local integration.

### 3. Rewire and validate

~~~text
python configs/source_root_workflow.py --update
python configs/source_roots.py show --format json
python configs/source_roots.py resolve --format json
python configs/source_roots.py verify
~~~

Only after show/resolve point at the manual checkout may dependency source be
edited and built. Every active-lock or manual-path change requires --update;
otherwise CMakePresets.json can retain an old root.

Then operate on Ravo only: configure/build as required and run Ravo tests only
for required behavior validation. Frozen 0.9 must not run. Windows example
(Test is optional):

~~~powershell
& .\Ravo\tools\freecm_project.ps1 -Action Configure -Configuration Debug
& .\Ravo\tools\freecm_project.ps1 -Action Build -Configuration Debug
& .\Ravo\tools\freecm_project.ps1 -Action Test -Configuration Debug
~~~

### 4. Publish the dependency before updating parent pin

When an integrated dependency has a commit the parent will consume, work from
the lower to higher levels of the dependency topology:

1. Validate, commit, and push in the real dependency repository.
2. Run git ls-remote <remote> <published-ref> and confirm the pushed branch/tag
   resolves to the target SHA.
3. Update the direct dependency commit in source_roots.lock.jsonc.in to the
   published SHA while retaining depsMode: pinned.
4. Change the same dependency in the local active lock back to the pinned SHA
   while preserving machine-local CMake configuration.
5. Run --update, verify, and affected Ravo configure/build/test again.
6. Commit only template, configuration/consumer code, and relevant documents;
   do not commit active lock, preset, or build directories.

Never make a parent lock, gitlink, or later commit depend on an unpublished
local-only dependency SHA. In multi-layer work, publish lowest dependencies,
then intermediates, then Ravo.

python configs/source_roots.py pin --dep <name> --ref <ref> resolves a ref from
a local seed and writes the active lock, but it cannot replace review of the
tracked template or prove remote publication.

## Common failures

| Symptom | Action |
| --- | --- |
| --update overwrote a change | You edited build/dependency_source_roots/*; switch the active lock to manual and edit a real checkout. |
| --update reports a missing seed | Explicitly run --init once; do not add a hidden network fallback to an offline path. |
| Build uses old source | Inspect active lock, run --update, then verify generated-preset roots with show/resolve. |
| Manual path is invalid | Check logical dependency name, absolute path, and required files; then run verify. |
| Nested pin conflict | Run graph, audit, and explain-conflict; repair the root or parent template that actually declares the conflict. |
| Seed has unknown changes | Stop automatic refresh, establish ownership, and never overwrite/delete developer changes. |
| Remote lacks pinned SHA | Push dependency, confirm the ref with git ls-remote, then update the parent template. |
| .freecm.workspace.lock times out | Identify the owner process in the report; do not let extension and Python workflow mutate the active lock simultaneously. |
| Cleanup may lose dependencies | Run --cleanbuild --dry-run, then --cleanbuild after confirmation; never delete dependency roots. |
| FreeCM checkout differs from gitlink | Inspect parent/submodule dirt and submodule prefix; run --remote --checkout only from parent root for an explicit refresh. |

Do not bypass this workflow through FetchContent, CMake downloads, replacement
submodules, source copies, or direct generated-directory patches.

## GitHub Actions

.github/workflows/ci.yml follows the same FreeCM path on clean runners: --init
creates an ignored active lock from the template; CI rewrites platform
CMAKE_PREFIX_PATH, RAVO_PACKAGE_RUNTIME_SEARCH_PATHS, and cmakeEnvironment.PATH
(Qt bin and host prefix) in that lock; then --update generates the preset. Every
platform builds with cmake --build build/<preset>. Linux's generated build
preset is ClangDebug, while Windows gtest discovery must inherit Qt bin written
to the lock and Path. The template, local active lock, and generated
CMakePresets.json are never CI outputs to commit. GitHub Actions installation of
GTest/Quill (and zlib/libpng on Windows) is runner-host preparation, not
FetchContent in Ravo's CMake graph.
